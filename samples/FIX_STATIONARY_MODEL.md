  モデルが片足を上げたままその場で留まる
  
【原因】
  1. 前進速度（tracking_lin_vel）のリワードが低い
  2. 足の滞空時間（feet_air_time）のリワードが相対的に高すぎる
  3. 交互性（feet_alternating_pos）のリワードが高すぎる
  → 結果: 片足を上げるだけで報酬を得られるため、歩く必要がない

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【解決策】

【ステップ1】前進を最優先にする（強制モード）

  $ python3 hrp2_auto_train_loop.py \\

      --max_iterations 500 \\
      --num_loops 3 \\
      --force_forward

  効果:
    - tracking_lin_vel = 10.0 (最大値)
    - feet_air_time = 0.5 (最小)
    - feet_alternating_pos = 0.5 (最小)
  
  結果:
    Loop 1: モデルが前に進もうとする
    Loop 2: ぎこちない歩き始める
    Loop 3: 歩行パターンが形成される

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  $ python3 hrp2_auto_train_loop.py \\

  自動調整:
    Loop 1-2: tracking_lin_vel を高く維持 (スコア低い)

【リワード設定の重要ポイント】

  初期値（前進優先版）:
    tracking_lin_vel: 5.0        ★ 最重要 (was 1.0)
    feet_air_time: 1.0           ★ 降下 (was 2.0)
    feet_alternating_pos: 1.5    ★ 降下 (was 3.0)

  比率を見ると:
    前進 : 足の動き = 5.0 : (1.0 + 1.5) = 5.0 : 2.5 = 2:1
    → 前進を足の動きの2倍重視

  従来の設定（問題）:
    tracking_lin_vel: 1.0
    feet_air_time: 2.0
    feet_alternating_pos: 3.0
    比率 = 1.0 : 5.0 = 1:5
    → 前進より足の動きを5倍重視！= 片足立ちで十分

【詳細: リワード関数の役割】

  tracking_lin_vel リワード:
    → ロボットが指令速度（例: 0.5 m/s）で移動しているか
    → 値が高いほど、速度誤差を小さくするよう学習
    → 「歩き続ける」を学習させる

  feet_air_time リワード:
    → 足が地面から離れている時間
    → 値が高いと、足を上げることだけで報酬を得る
    → しかし「前進」と組み合わなければ片足立ちで良くなる

  feet_alternating_pos リワード:
    → 左右の足が交互に出ているか
    → 初期状態では、交互に足を上げる良い行動を学習
    → ただし「前進しながら」という制約がなければ、
      その場で片足ずつ上げるだけで報酬を得る

【補足: なぜこの問題が起きたか】

  強化学習では、エージェントは「報酬を最大化する行動」を学習します。
  
  従来の設定:
    総報酬 = 1.0×前進 + 2.0×滞空 + 3.0×交互
    
  片足立ちの場合:
    前進: 0 (動かないので 0)
    滞空: 1 (片足は浮いている)
    交互: 0 (交互に動かないので 0)
    総報酬 ≈ 2.0 × 1 = 2.0 ✓ これで十分！
    
  修正後の設定:
    総報酬 = 5.0×前進 + 1.0×滞空 + 1.5×交互
    
  片足立ちの場合:
    総報酬 ≈ 1.0 × 1 = 1.0 ✗ 低い！
    
  前進しながら交互に歩く場合:
    前進: 1 (移動している)
    滞空: 0.3 (時々浮いている)
    交互: 0.8 (左右が交互)
    総報酬 ≈ 5.0 × 1 + 1.0 × 0.3 + 1.5 × 0.8 = 6.7 ✓ 最大！
    
  → 歩くことが「報酬を最大化する最適戦略」になる
